# Разбор проекта и план выхода в прод

## Баги и проблемы исходного проекта

### Критично
1. **Ключ jsonbin в `src/main.js`** зашит в клиентский код и выставлен заголовком по умолчанию для всех запросов axios:
   его видит любой посетитель, и он уходит на любой другой домен. Перевыпустить, считать скомпрометированным.
2. **jsonbin как база** — лимиты, нет блокировок и контроля доступа. Для прода не подходит.
3. **Картинки:** баннеры по 35–39 МБ (PNG), продублированы в `src/assets` и `public/img`. Архив 251 МБ.

### Функциональные
- Модалка бронирования не работает: нет `v-model` у полей, нет обработчика кнопки, время не сохраняется,
  сумма не считается за ночи, опечатка «KZt».
- Поиск по датам ничего не делает: даты не используются, занятость не проверяется.
- `RentListPage`: `watchEffect` создаётся после `await` (не привязан к компоненту); цена и теги применяются
  по кнопке, сортировка — мгновенно.
- Правило `* { @apply text-black }` перебивает наследуемый цвет: чёрный текст отзывов на бирюзовом фоне.
- Шкала отступов Tailwind непоследовательна (`gap-8` = 8px, `gap-10` = 40px); классы `w-704`, `min-w-[490]`,
  `text-1xl` не существуют; брейкпоинт `sm` переопределён как max-width.
- Шапка на телефоне: бургер написан, но не подключён.
- `scrollBehavior` всегда скроллит вверх — «Назад» теряет позицию.
- Scoped-стиль точек Swiper не применялся; миниатюры галереи налезали на контент; у всех карточек одно фото.
- Нет состояний загрузки/ошибки/404 на странице квартиры.
- Пустые `href` в футере (нужны `tel:`/`mailto:`), пустая ссылка на соглашение, `<html lang="">`, нет meta.
- Мёртвые зависимости (FontAwesome ×4, `vue-tailwind-datepicker`, `fast-glob`), имя пакета `package.json`.

## Что изменено при переносе
- Nuxt 4, SSR, TypeScript, `@nuxt/image` + WebP (баннеры ~250 КБ вместо ~37 МБ).
- Данные квартир отдаёт сервер (`/api/apartments`), клиент больше не ходит в jsonbin и не знает ключей.
- Цена считается на сервере; проверка пересечения дат; honeypot и rate limit на `/api/bookings`.
- Pinia заменена на `useState`; нативные `<input type="date">` вместо `@vuepic/vue-datepicker`.
- Теги фильтра строятся из данных, диапазон цены — из реальных цен.
- Контакты — в одном файле `app/utils/site.ts`.
- Удалены страницы Форма, Тест, Игра, компонент `test.vue` и заглушка `RentObjectPage`.

## Ограничения текущей версии (осознанные)
- Хранилище заявок — файлы в `.data/`: годится для MVP на одном сервере. Блокировка от двойной брони
  работает внутри одного процесса. Для прода — PostgreSQL с транзакциями.
- Rate limit в памяти процесса; за nginx/Cloudflare настройте лимиты и там.
- Нет автотестов; `npm install` и сборка при подготовке этой версии не запускались (не было сети) —
  при первом запуске возможны мелкие правки.
- Ссылка на Booking.com в `site.ts` — заглушка. Страница пользовательского соглашения не создана.

## Дорожная карта
1. **Прод:** VPS (Node 22 + nginx + HTTPS), PostgreSQL вместо JSON/файлов, бэкапы, мониторинг ошибок.
2. **Админка:** либо готовая CMS (Directus / Strapi / Payload) поверх Postgres, либо своя в Nuxt
   (авторизация, CRUD квартир, загрузка фото, календарь броней). Репозиторий `server/utils/apartments.ts`
   — единственное место, которое придётся заменить.
3. **Bitrix24:** лид создаётся через `crm.lead.add` (`server/utils/crm.ts`). Если на портале «простой CRM»
   (только сделки) — заменить на `crm.contact.add` + `crm.deal.add`. Для обратной связи (статус сделки →
   сайт) нужен исходящий вебхук.
4. **Оплата:** бронь в статусе «ожидает оплаты» → ссылка на оплату → статус «оплачено» только по вебхуку
   провайдера (не по редиректу браузера). Провайдера для Казахстана выбирать после проверки актуальных
   условий; в текущей версии оплата при заселении.
5. **Прочее:** страница соглашения/политики, sitemap и robots, аналитика, автотесты API.
